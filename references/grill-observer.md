# 拷问-观察双 agent · 找设计缺口

目的:验证「写下来的流程/设计文档」的完备性——坑是否被**直接解释并给出处理**。

## Agent A(拷问者)的方法论:design-tree grilling

A 不是散弹式乱问,而是按 grilling skill 的设计树方法论出题:

- 把设计映射为**决策树**:每个决策分叉出依赖它的子决策;
- 按**轮次(rounds)**推进:每轮只问「前沿(frontier)」——即前置决策已落定、
  现在就能问的问题;一轮把整个前沿问完(编号 Q1..Qn,每题附 A 自己的推荐答案),
  等回答再算下一轮前沿;
- 依赖未落定问题的问题留到后续轮,不抢跑;
- **找事实是 A 的活,不是用户的**:需要环境事实(文件/工具/接口行为)时自己查
  或派子 agent,不拿「你确认下 X」烦用户;**决策**才交给人;
- 结束条件:前沿为空——每条分支都问过,没有沉默假设。

针对流程/系统验证,A 的提问至少覆盖这些维度(每页文档 ≥10 问,防走过场):

- 每步失败模式:超时、错误、部分失败、重试、幂等;
- 并发与乱序:并发到达、重复投递、迟到写;
- 权限与边界:谁有权触发/看到/篡改;越权路径;
- 状态机角落:终态后再来事件、回滚、崩溃恢复点;
- 数据一致性:两存储写一半;缓存与真源背离。

题目格式(grilling 原版):

```
❓ **Q1** - **<题名>**: <题干,可多选>
➡️ <拷问者自己的推荐答案>
```

## Agent B(观察者)的核对规程

拿 A 的题单逐条核对流程文档,三分类,输出逐条表格(题目→分类→文档位置/回流去向):

- ✅ 已覆盖:文档明确解释并给出处理(标注位置);
- ⚠️ 含糊:提到但没说清边界条件 → 改文档;
- ❌ 缺口:无任何解释 → 回流:可形式化的建 TLA+ 不变量;可机器强制的加 lint/类型禁掉;其余补文档。

❌ 缺口项全部要有回流去向,不许挂「待讨论」。

## 执行细则

- **拷问者与观察者不得同族模型**(自我背书无效);
- B 合并陈述视为无效,必须逐题出表;
- A 可引用但不重复 B 侧的文档结论,保持出题独立性。

## 派发示例(按 AGENTS.md 执行者路由)

```bash
# A 拷问:贴 grilling 方法论 + 流程文档原文,只出题
agy --model gemini-3.8-flash-medium -p "<grilling 方法论> + <流程文档> + 指令:按 design-tree/rounds 出题,只出题不回答"
# B 观察:另选非同族席位逐条核对(或本会话承担,但 A 必须外部)
```
